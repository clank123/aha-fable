# 30-Second Demo

这是一个脱敏的短示例，用来快速展示 Aha Fable 到底做什么。

## Input

```text
我总是把工作整理成系统、表格和长期方法。
我给团队讲的时候，大家都点头。
但一到执行，他们只问：
今天发什么？
谁负责？
明天怎么知道有没有用？

我怀疑他们是不理解长期价值。
```

## Output

**判断**

问题不是系统错了，而是系统还没有被压成一个高压现场里人人都能拉动的手柄。

**寓言**

海边有个港务官，做了一张港口里从未有过的精密大图。

图上画着潮水、缆绳、仓库、船只、灯塔和风向。站在钟楼上，他能解释每一个码头为什么重要，也能说清整个港口该如何像一台机器一样运转。

后来，大雾来了。

三艘船同时靠岸。一艘装着天亮前会坏掉的水果，一艘装着不能淋雨的布，一艘桅杆裂了，只能靠最安静的码头。

港务官摊开大图，开始解释。

水手们在雾里喊：

“我现在拉哪根绳？”

“先开哪个仓？”

“到底哪艘船先进来？”

天亮时，水果软了，布有了雨味，那艘坏船也漂去了隔壁港。

第二天夜里，老守钟人在钟楼下挂了一块小木牌。

木牌上只有三行字：

水果船先靠。

布进东仓。

空手的人去二号码头。

那张大图还在钟楼里。

但雾里的所有人，先看那块木牌。

**揭露**

这个概念叫：复杂系统需要一个主控柄。

大图对应长期方法，浓雾对应真实执行压力，小木牌对应最小操作手柄：先保什么、谁先动、明天看什么信号。

**行动**

每次做完复杂分析后，强制再写一个高压版本：

```text
这次先保：___
今天只做：___
明天只看：___
```

**灵魂反问**

如果没有人被允许研究你的整张大图，他们今天唯一应该拉动的那根手柄是什么？
