# Aha Fable 产品说明书

## 产品名

**Aha Fable（啊哈寓言）**

备选中文名：啊哈寓言、故事照妖镜、寓言反问器。

最终推荐：**啊哈寓言**。理由是短、好记，并且直接指向产品结果：让读者出现一次 "aha moment"。

## 产品定位

Aha Fable 是一个用于 AI Agent 的 skill。它把用户的近期笔记、反思、会议材料、授权 AI 对话摘要或抽象概念，转成一个间接的寓言故事，并在故事后揭示隐藏原则，给出一个行动反问。

它不是文章代写器，也不是知识总结器。它服务的是：

> 把一个已经隐约存在、但还没被真正看见的高阶判断，变成能被记住、能被传播、能指导行动的故事。

## 来源与改造说明

Aha Fable 的起点不是原创发明，而是对网上流传的 Anthropic / Amanda Askell 相关寓言式概念解释提示词的二次改造。

原始方向的核心是：让 AI 用一个间接寓言解释概念，并在结尾揭示概念名称。

Aha Fable 保留这个“延迟揭示”的优势，但做了四个增强：

1. **从解释概念变成诊断经验**：用户不一定先给概念，也可以给 flomo、Get Notes、复盘材料或 AI 对话摘要。
2. **从单次 prompt 变成可复用 skill**：有触发条件、输入边界、输出格式、质量标准和校准示例。
3. **从学习理解变成行动转译**：输出不止故事和解释，还必须给一个行为改变。
4. **从故事结尾变成反问结尾**：用一个灵魂反问把概念压回现实行动。

## 用户痛点

### 1. 抽象洞见难以被别人接住

用户常常能从复杂实践里看到原则，但讲出来时容易变成一堆概念、流程和解释。听众理解成本高，行动意愿低。

### 2. 笔记里有信号，但缺少穿透性表达

flomo、日记、会议纪要里经常藏着真正的盲点，但普通总结只会复述材料，不能把盲点变成一个可记忆的故事。

### 3. 方法论容易变成说教

直接讲道理会让人防御。寓言绕开防御，让读者先跟着情节走，最后自己意识到问题。

## 目标用户

- 持续写笔记、做复盘、建立个人知识系统的人。
- 使用 flomo、Get Notes、AI 对话记录沉淀洞察的人。
- 创始人、经营者、咨询顾问、内容创作者。
- 需要把复杂方法论讲给团队、客户或公众的人。
- 正在用 AI 协作整理思想、生产内容、沉淀方法论的人。

## 核心使用场景

### 场景 1：从近期笔记中找盲点

用户提供最近几条 flomo 或复盘材料，Aha Fable 找出一个高阶疏忽，并写成寓言。

### 场景 1B：从 AI 对话中提取洞察

用户明确授权后，提供最近 AI 对话摘要或片段，Aha Fable 识别其中反复出现但尚未命名的原则，并写成寓言。

### 场景 2：把一个抽象概念讲明白

用户给出概念，例如“长期系统必须寄生在当下需求上”，Aha Fable 写出故事、揭露和行动反问。

### 场景 3：为文章或口播提供内容钩子

用户要做公众号、短视频、课程或内部分享，Aha Fable 先给出一个可传播的故事核心。

### 场景 4：自我提醒和每日学习

用户每天从自己的知识库里抽一个概念，用寓言方式复习，降低认知负担。

## 输入要求

最低输入：

- 一个概念；或
- 一组笔记；或
- 一组会议记录；或
- 一组经用户授权的 AI 对话摘要；或
- 一个最近困扰用户的真实问题。

更好输入：

- 近期背景。
- 目标听众。
- 用户希望被点醒的方向。
- 不可公开的隐私边界。

## 输出格式

```markdown
**判断**

一句话指出材料背后的真正压力。

**寓言**

完整故事。故事里不直接说出概念名，也不使用原领域术语。

**揭露**

说出概念名称，并把故事关键情节对应到真实概念。

**行动**

一个可执行的行为改变。

**灵魂反问**

一个直指行动的反问。
```

## 质量标准

一条合格输出必须满足：

- 故事里有主角、目标、误判、代价、细节反转。
- 前 80% 不讲道理，只讲故事。
- 结尾揭示感强，不提前说破。
- 概念解释短，不重新复述故事。
- 灵魂反问能指导下一步行动。

失败输出包括：

- 披着故事外衣的概念解释。
- 没有冲突、代价和反转。
- 用很多抽象词替代具体情节。
- 结尾只有鸡汤，没有行动问题。

## 与普通提示词的区别

普通提示词通常要求“写一个寓言解释概念”。这会让模型写出好懂但无张力的故事。

Aha Fable 增加了四个约束：

1. 先诊断隐藏压力。
2. 故事必须有错误判断和代价。
3. 概念名必须延后揭示。
4. 结尾必须落到行动反问。

## 安装方式

将 `skill/aha-fable` 复制到你的 Codex skills 目录。

示例：

```bash
cp -R skill/aha-fable ~/.codex/skills/aha-fable
```

然后在新对话中使用：

```text
使用 aha-fable，把下面这段反思变成一个寓言，并给出概念揭露和灵魂反问。
```

## 数据边界

- skill 本身不需要网络。
- skill 不保存用户数据。
- 公开示例必须脱敏。
- 私人笔记、Get Notes 原文、AI 对话原文、公司经营数据、客户信息、会议原文不得直接放入公开仓库。
- 分析 AI 对话必须基于用户明确授权提供的内容或摘要；不得默认读取用户历史对话。

## 最小案例

输入：

```text
我发现团队不愿意配合长期系统，因为他们看不到短期回报。
```

输出方向：

```text
寓言：修水渠的匠人发现，村民不是看不见十年后的池子，而是今天手里的水桶勒手。
揭露：长期系统必须寄生在当下需求上。
反问：如果你不允许自己再解释长期价值，能不能把它变成对方今天就会主动伸手来拿的东西？
```
